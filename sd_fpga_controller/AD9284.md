# AD9284 finite capture and AXI FIFO connection

## Implemented boundary

`ad9284_to_axis` is an Artix-7 receiver for the AD9284's **eight shared
differential LVDS data lanes and differential DCO**. Both ADC channels are
captured at a nominal **100 MSamples/s per channel** using DDR input registers.
The 100 MHz AXI clock is a separate domain; equal nominal frequencies do not
make the clocks synchronous.

The implementation follows the pin table and switching specifications from the
user-supplied [AD9284 Rev. B datasheet](https://www.analog.com/media/en/technical-documentation/data-sheets/ad9284.pdf):

| ADC connection | ADC package pins | FPGA top-level port |
| --- | --- | --- |
| D0+ / D0- (LSB) | 10 / 9 | `adc_data_p(0)` / `adc_data_n(0)` |
| D1+ / D1- | 12 / 11 | `adc_data_p(1)` / `adc_data_n(1)` |
| D2+ / D2- | 14 / 13 | `adc_data_p(2)` / `adc_data_n(2)` |
| D3+ / D3- | 16 / 15 | `adc_data_p(3)` / `adc_data_n(3)` |
| D4+ / D4- | 20 / 19 | `adc_data_p(4)` / `adc_data_n(4)` |
| D5+ / D5- | 22 / 21 | `adc_data_p(5)` / `adc_data_n(5)` |
| D6+ / D6- | 24 / 23 | `adc_data_p(6)` / `adc_data_n(6)` |
| D7+ / D7- (MSB) | 26 / 25 | `adc_data_p(7)` / `adc_data_n(7)` |
| DCO+ / DCO- | 18 / 17 | `adc_dco_p` / `adc_dco_n` |

These are **ADC package pins**, not FPGA package pins. FPGA pins intentionally
remain unassigned until the board/connector is selected. Treat this as a custom
differential PCB interface, not as arbitrary single-ended Pmod wires.

There are no serial sample inputs and no sample SPI transactions. The ADC's
three-wire SDIO/SCLK/CSB port is for configuration, not the sample data path.
The generic SPI master wrapper described below is **not an AD9284 configuration
controller**: it has separate MOSI/MISO and releases CS every byte. The AD9284
uses a multi-byte instruction and bidirectional SDIO. Also its configuration
SCLK period must be at least 40 ns (at most 25 MHz), unlike the generic
50 MHz data-transfer example.

## Physical receiver

`ad9284_lvds_rx` uses Xilinx `IBUFDS`, `MMCME2_BASE`, `BUFG`, and `IDDR`
(`SAME_EDGE_PIPELINED`) primitives. The default MMCM settings are:

* DCO input: 100 MHz, 10 ns period.
* VCO: 1000 MHz (multiply by 10).
* DDR capture clock: 100 MHz, **90 degrees delayed** (divide by 10).
* The quarter-cycle shift places capture edges near the middle of the
  half-cycle data windows instead of at the DCO/data transitions.

`capture_phase_degrees` is exposed for actual board timing closure, not
automatic calibration. The default 90-degree phase must be checked against
Figure 2, ADC/FPGA timing, and PCB skew.

`rising_is_a = true` assigns the captured rising half-cycle to channel A and
the following falling half-cycle to channel B; `false` exchanges them.
**The supplied text extraction does not preserve the diagram's graphical
channel/edge alignment**, so the default is an explicit selectable convention,
not a verified assertion of the ADC's hardware channel order. Check the
original timing diagram and distinguish the two channels using a known
channel-specific input/test pattern before accepting sample identity and
simultaneous-pair alignment. `pair_previous_falling = true` pairs a rising-edge
sample with the **preceding** falling-edge sample instead of the following one;
select this if the documented channel sequence crosses the cycle boundary.
Both channel orders and both pair alignments are covered by functional tests.
Swapping labels alone cannot fix a one-sample offset.

`differential_termination` defaults to false: provide board-level 100-ohm
differential termination unless the selected FPGA bank supports and enables
appropriate internal termination. The receiver declares `LVDS_25`; verify
bank voltage, common-mode/input limits, package differential pairs, clock
routing, and connector availability against the Artix-7 and Basys 3
documentation before making the PCB. ADC driver supply voltage is not the
same thing as FPGA I/O-bank voltage.

The ADC input sampling clock, analog front end, supplies, reference, OE, and
configuration are outside this module. Supply a suitable low-jitter 100 MHz
encode clock to ADC CLK+/- separately and keep OE low to enable outputs.
Do not drive ADC 1.8 V control pins directly from incompatible FPGA outputs.

## Triggered capture

`ad9284_capture` is the portable RAM/CDC/packet core. It can also be used with
already-captured `sample_a`, `sample_b`, `sample_clk`, and `sample_valid` inputs.

The top-level controls all use the AXI clock domain:

| Port | Meaning |
| --- | --- |
| `aclk` | 100 MHz AXI clock |
| `aresetn` | Active-low common reset, clears/aborts the complete unit |
| `trigger` | Rising-edge trigger; synchronized internally |
| `adc_locked` | MMCM lock status synchronized into `aclk` |
| `ready` | Unit idle, reset released, ADC clock locked |
| `busy` | Acquisition or AXI drain in progress; also high in fault state |
| `done` | One-cycle pulse after the final AXI beat is accepted |
| `capture_fault` | Sticky clock-lock-loss error during acquisition; reset required |

Hold an asynchronous trigger level for at least three AXI clock periods so it
can cross the synchronizer. There is no pretrigger history and no deterministic
sub-cycle external-trigger timestamp. Capture starts after trigger detection,
the cross-domain request synchronizer, and receiver pipeline latency.

The default `capture_pairs = 1024` captures **1024 consecutive simultaneous
sample pairs**, requiring 2048 bytes of local RAM (512 x 32 bits).
The generic must be even and at least two. Acquisition lasts 10.24 us at
100 MSamples/s, excluding synchronization/start latency.

Only one capture can be outstanding:

1. A trigger rising edge is accepted only when ready.
2. The sample domain owns the RAM and stores the entire acquisition, regardless
   of AXI backpressure. The ADC itself keeps converting continuously.
3. A two-stage completion synchronizer transfers RAM ownership to AXI.
4. AXI reads/drains the stored packet; RAM contents remain unchanged while
   the consumer is stalled.
5. The final accepted beat pulses done and releases busy.

Triggers while busy are **ignored, not queued**. A trigger held high across
completion does not automatically start another capture. Return it low and
create a new rising edge after ready.

Reset flushes partial acquisition, a pending packet, and all handshake state;
it does not clear the RAM physically. No stale RAM contents are published after
reset. Distribute the same reset to the attached FIFO, or reset/flush its partial
packet separately before restarting. Reset deassertion is synchronized locally
in the capture and receiver domains.

Loss of MMCM lock during acquisition latches `capture_fault`, suppresses
publication of that acquisition, and holds busy until reset. A previously
completed packet can finish draining if lock is lost afterward: its samples
are already safely stored. Ready remains low while the ADC clock is unlocked.

## Common 32-bit packet format

Both `ad9284_to_axis` and `spi_master_to_axis_fifo` output:

* 32-bit `m_axis_tdata`.
* `m_axis_tvalid` / `m_axis_tready`.
* `m_axis_tlast` on the final beat of each packet.
* Four valid bytes per beat; no `TKEEP`, no short final beat, no headers.
* Stable DATA/VALID/LAST until a rising `aclk` edge accepts the beat.

ADC packing is little-endian by byte lane:

```text
bits [ 7: 0] = A[2*k]
bits [15: 8] = B[2*k]
bits [23:16] = A[2*k+1]
bits [31:24] = B[2*k+1]
```

The default acquisition is one **2048-byte packet / 512 beats**.
ADC codes are preserved as received; no conversion between offset binary,
two's complement, or Gray code is performed.

`spi_master_to_axis_fifo` wraps the existing byte-wide `spi_master_to_axis`
without changing its ports or behavior. Its TX input stays byte-wide.
It packs four sequential received MISO bytes per output beat, oldest in [7:0].
`packet_bytes` defaults to **256 bytes / 64 beats**, and must be divisible by
four. CS still deasserts after each byte. Supply exactly the desired packet's
TX byte count; stopping early leaves an incomplete packet buffered until
more TX bytes arrive or reset discards it. There is no timeout/automatic flush.

At the default 100 MHz clock/divider 1, the FIFO-compatible SPI wrapper
preserves roughly 42 Mbit/s payload throughput with an unstalled consumer.
It propagates backpressure through its formatter and RX result slot, so it
can finish an already-started transaction but does not overflow storage.

## Wiring AXI FIFO MM S

In Vivado use **Add Module** -> `ad9284_to_axis`. For the SPI path, add
`spi_master_to_axis_fifo` instead of the older byte-output bridge.
No separate capture RAM, SPI master, or packetizer block is needed beside
these top modules.

Connect either source to the FIFO's **S_AXIS_RXD** receive-stream interface:

| Source | FIFO MM S destination |
| --- | --- |
| `m_axis_tdata[31:0]` | `axi_str_rxd_tdata[31:0]` / S_AXIS_RXD TDATA |
| `m_axis_tvalid` | `axi_str_rxd_tvalid` / S_AXIS_RXD TVALID |
| `m_axis_tlast` | `axi_str_rxd_tlast` / S_AXIS_RXD TLAST |
| `m_axis_tready` (input) | `axi_str_rxd_tready` (output) / S_AXIS_RXD TREADY |
| Same 100 MHz clock | FIFO AXI/receive interface clock inputs |
| Same active-low reset | FIFO AXI/receive reset inputs |

If optional FIFO receive sidebands are exposed, tie unused TUSER/TID/TDEST
inputs to zero; if TKEEP is enabled, all four bytes are valid (`0xF`).
The project's current FIFO has 32-bit receive data and TKEEP disabled.

**Do not connect the ADC and SPI outputs directly to each other or both
to one FIFO input.** Use separate FIFOs or a packet-aware AXI4-Stream
arbiter/switch that holds the selected source until TLAST. A combinational
data mux without matching valid/ready/last arbitration will corrupt packets.
Identical stream formats do not identify the source: use separate queues,
an out-of-band source selection, or a later explicitly designed packet header.

### FIFO depth and processor readout

The existing block is configured for **512 RX words** with RX cut-through
disabled. That equals the ADC payload alone and leaves no margin for the
FIFO's effective usable capacity/internal bookkeeping. **Reconfigure it to
at least 1024 RX words** before the default 512-beat capture is used.
Check the IP's actual maximum packet size in its generated configuration and
PG080. This implementation does not silently modify the existing block design.

With store-and-forward operation, a packet larger than usable FIFO capacity
can stall before TLAST; the processor cannot rely on a completed packet being
available to drain it. The capture RAM preserves data under this stall but
does not solve the FIFO capacity deadlock.

Connect the FIFO's memory-mapped AXI slave to a processor/AXI master and assign
its address range to read registers. The module itself does not create a CPU,
AXI interconnect, address map, or software driver. The FIFO's RX packet-length
register reports packet size in **bytes** (2048 ADC / 256 default SPI);
drain exactly the corresponding data words using the IP's documented
register/interrupt protocol. An AXI stream FIFO alone has no processor register
interface; AXI FIFO MM S is the appropriate existing IP for that use case.

## Constraints and board bring-up

No package-pin or delay constraints are guessed. Before generating a bitstream:

1. Assign all nine differential pairs to valid FPGA P/N pairs; DCO must use a
   clock-capable input with legal MMCM/BUFG routing.
2. Constrain `aclk` to 10 ns and ADC DCO to 10 ns. Let Vivado derive the
   MMCM output clocks and phase relationships.
3. Apply DDR input delays to both DCO edges using the actual ADC data/DCO
   skew specification, PCB differential/data-to-clock skew, and uncertainty.
   The supplied datasheet lists DCO/data skew -280..+100 ps; verify the
   reference/sign in Figure 2 before converting it to XDC delays.
   At 100 MHz each LVDS lane carries 200 Mbit/s with a 5 ns half-cycle window.
4. Preserve `ASYNC_REG`. Except only request/complete/lock/trigger/reset
   first-stage asynchronous crossings as appropriate, and review the
   dual-port RAM ownership handshake in `report_cdc`. Do not false-path
   input DDR data or the whole design to hide timing violations.
5. Check inferred RAM, MMCM settings, IDDR placement, DRCs, setup/hold,
   reset recovery/removal, and `report_timing_summary`.
6. Use known ADC patterns and distinguishable A/B inputs to validate bit
   order, polarity, channel order, sample pairing, and capture phase.
7. Verify the complete FIFO packet length/readout before enabling real triggers.

The 200 MB/s raw ADC input is captured locally; it does not require software
to sustain that rate during a finite acquisition. This single-buffer design
has dead time while draining and cannot continuously capture/retrigger at
100 MSamples/s. The simple synchronous RAM drain takes three AXI cycles per
beat without stalls (about 15.36 us for 512 beats).

## Integration and verification

Source `import_spi.tcl` in the open Vivado project to register all new RTL
and testbenches. Its existing default top selection remains the slave SPI
bridge/bench; choose `ad9284_to_axis` or add it to your block design explicitly.
The GHDL-only functional primitive models are **not** imported into Vivado.
Vivado simulation uses its actual UNISIM library.

```sh
bash tests/run_acquisition_ghdl.sh
bash tests/run_ghdl.sh
```

The acquisition suite runs 13 simulations: capture with three independent
clock ratios; both receiver channel mappings and pair alignments; two packet sizes; and SPI
packet output in all four modes. It checks 1024-pair sample continuity,
byte packing, exact TLAST boundaries, repeated/ignored/held-high triggers,
backpressure, reset during capture/drain, clock-loss fault handling,
and SPI throughput >=32 Mbit/s.

GHDL synthesis checks the portable capture core, formatter, and all four SPI
wrapper modes. The physical receiver is tested only with **functional-only
primitive substitutes** in `tests/models/`: these validate wiring and
behavioral phase/DDR sequencing, not silicon timing, electrical performance,
MMCM lock dynamics, or hardware compatibility. Vivado synthesis,
implementation, CDC analysis, and physical-board validation remain required.
